---

Players across Ghana and Africa develop with zero performance tracking, health monitoring, or structured feedback. Elite talent in Kumasi, Tamale, and Accra goes unnoticed because there is no platform to surface it to clubs globally. Even gifted players lack training structure, injury prevention, and a clear development pathway from youth to professional.

---

## The Founders

Augie grew up in Ghana and experienced the raw talent and total absence of structure in African football. He later played in the USA and saw what world-class data, coaching infrastructure, and player support looks like. His vision is to give African players the same tools he has been provided in America.

Paula translated that mission into an AI-powered athletic performance platform built for Ghana and Africa from U10 academy players to professional athletes.

---

## HappyFeet Roles

**Players** track their development journey through performance ratings, health logs, training plans, achievements, and a faith and purpose section grounded in the values of African football culture.

**Coaches** manage their squads through session building, player tracking, health and wellness monitoring, recruitment pipelines, and AI-assisted performance insights.

**Scouts** discover and place talent through prospect pipelines, club networks, placement records, and AI-generated scouting reports that connect African players to opportunities worldwide.

**Admins** verify squads and agencies, manage users, handle support tickets, and oversee platform activity through a dedicated admin panel.

### Design system

The UI is built on a custom editorial design system with sharp corners, condensed uppercase typography, a black and gold palette, and a newspaper-style layout language. Fonts are **Chakra Petch** (headings) and **Inter** (body). Icons are **Tabler Icons 2.47.0** (pinned to prevent slow-network crashes).

Dark and light mode are fully supported and persist across sessions.

### Database

**Supabase** (PostgreSQL) handles all data persistence. The `db.js` module is an async abstraction layer so the underlying database can be swapped without touching any other file.

All tables have Row Level Security enabled with `allow_all` policies (to be tightened in v2). Real-time subscriptions are enabled via `REPLICA IDENTITY FULL` on all key tables.

| Table | Purpose |
|---|---|
| `users` | All roles. Profile JSONB, squad/agency status, auth fields, password history |
| `squad_verifications` | Coach squad registration + admin approval workflow |
| `agency_verifications` | Scout agency registration + admin approval workflow |
| `squad_invites` | Coach→player invites with 24hr decline cooldown |
| `session_ratings` | Coach ratings per player (1/day unique constraint, re-editable) |
| `health_logs` | Player daily wellness check-ins (1/day, re-editable) |
| `training_logs` | Player session completion logs |
| `training` | Player training plan + schedule |
| `health` | Player health data |
| `tracker` | Player tracker data |
| `messages` | Thread-based in-app messaging between all roles |
| `agent_conversations` | DribbleBot AI conversation history per user |
| `trial_requests` | Player trial requests to coaches |
| `scout_club_requests` | Scout network access requests to coaches |
| `scout_prospects` | Saved prospects with pipeline stages + AI report JSONB |
| `tickets` | Support tickets with embedded message thread (JSONB) |

### Authentication

HappyFeet uses a custom auth system on top of Supabase's database layer.

- Passwords hashed with SHA-256 via Web Crypto API
- Sessions stored in `sessionStorage` (tab-isolated)
- Login lockout after 5 failed attempts (15 min)
- Security question for password recovery (3-step flow)
- Security answer lockout after 4 failed attempts (15 min)
- Password history: last 5 passwords blocked on reset
- Password version tracking: force logout all other sessions on password change
- Banned users blocked at login with reason shown
- Kicked users blocked with countdown shown

**Signup flows:**
- Players: contact → role fields → security question → confirm
- Coaches: contact → role fields → security question → confirm → squad verification
- Scouts: contact → role fields → security question → confirm → agency verification

**Admin:** separate login screen, stored in `users` table with `role: 'admin'`. Multiple admins supported, and all receive real-time notifications for key events.

### Real-time

All key events delivered in real-time via Supabase Postgres Changes:

| Event | Effect |
|---|---|
| New message | Badge update + thread append for recipient |
| New ticket | Admin badge update, auto-refresh tickets view |
| Ticket claimed/replied/resolved | User toast notification + badge update |
| Squad/agency verified | Coach/scout nav rebuilds, full access unlocked |
| Squad/agency rejected | Toast notification + dashboard banner |
| Password changed | Force logout all other sessions |
| User banned/kicked | Force logout on next navigation |

### Messaging

- Thread-based with full conversation history
- Multi-recipient compose with tag-style input
- Emoji picker with confetti animation on emoji-only messages
- Archive / unarchive (full thread)
- Reply, view profile, and report actions
- System messages (from HappyFeet) shown separately

### Support tickets

All roles can submit support tickets via the Contact Support flow:

- Categories: General, Verification, Account, Technical, Report a user, Other
- Admins see all tickets in sections: Unclaimed, My tickets, Handled by others, Resolved
- Admins claim tickets before responding (prevents duplicate handling)
- Real-time badge updates for admins on new tickets
- Users notified in real-time when ticket is claimed, replied to, or resolved
- Users can mark tickets resolved or reopen them

### Verification workflows

**Coach squad verification:**
1. Coach submits squad details
2. Admin claims verification ticket, reviews it, and can edit details if necessary
3. Coach accepts or declines admin edits
4. Admin approves or rejects
5. On approval, full nav unlocks in real-time

**Scout agency verification:**
1. Scout submits agency details with regions and target leagues
2. Admin claims, reviews, approves or rejects
3. On approval, all scouting features unlock in real-time

### User management (admin)

- Ban with reason: blocked at login indefinitely
- Kick for 1 hour: auto-expires
- Unban previously banned users
- Users page shows all roles in collapsible sections

## AI Features

### DribbleBot
- Floating chat agent on all dashboards
- Powered by Claude Sonnet via Netlify Function proxy
- African football-focused system prompt
- Structured response format (sections, bullets, follow-up question)
- Full conversation history saved and restorable from dashboard

### AI Scouting Report
- Scout inputs observations → Claude generates structured report
- Saved to `scout_prospects.report` JSONB
- Downloadable as `.md` or PDF (jsPDF)
- Shareable to coaches via messaging

## Hosting

HappyFeet is deployed on **Netlify** from the `main` branch.

Netlify was chosen over GitHub Pages because it supports custom HTTP response headers, required for the Content Security Policy that allows the Supabase JS client and Anthropic API calls to function correctly.

```toml
[[headers]]
  for = "/*"
  [headers.values]
    Content-Security-Policy = "default-src 'self'; script-src 'self' 'unsafe-eval' 'unsafe-inline' https://cdn.jsdelivr.net https://fonts.googleapis.com; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com https://fonts.gstatic.com https://cdn.jsdelivr.net; font-src 'self' https://fonts.gstatic.com https://cdn.jsdelivr.net; connect-src 'self' https://*.supabase.co wss://*.supabase.co https://api.anthropic.com https://cdn.jsdelivr.net; img-src 'self' data: blob: https://*.supabase.co;"
```

### Local development

```bash
npm install -g netlify-cli
netlify dev
```

The AI agent only works on the live site or via `netlify dev`, not via `file://` access.
